# Tonight's Team Meeting – Asteroid Final Project

## Meeting goal

Agree on how the group will understand the approved dataset, develop research questions, and divide the first tasks. Do not force final research questions before checking the actual columns, missingness, and feasibility.

## Suggested agenda

### 1. Re-read the 2026 assignment (10–15 min)

Confirm:
- Total questions = 2 × number of members.
- Each member owns two questions.
- At least one question is an ML question.
- Each Non-ML question uses at least two D1–D6 criteria.
- Across the Non-ML questions, at least four of the six criteria are covered.
- Each question needs analysis, explicit numerical answers, and at least two well-labelled plots.
- ML needs at least two ML models plus one trivial baseline.

### 2. Understand the dataset (20–30 min)

Together inspect:
- Exact CSV filename, number of rows and columns.
- Meaning of one row.
- Data dictionary / meaning and units of columns.
- Numerical, categorical, identifier, and date/time columns.
- Missing values, duplicates, suspicious values, and possible outliers.
- Dataset source, collection method, license, and update/version information.

Do not assume a column's meaning from its name alone; verify it from dataset documentation.

### 3. Search prior work (15–20 min)

Each member searches for:
- Existing Kaggle notebooks using this dataset.
- Research papers or reports using the same or related asteroid data.
- Existing questions and methods.

Record URLs, authors, dates, and what will be different in this project. Do not copy questions or code without attribution.

### 4. Brainstorm research questions (20–30 min)

For every candidate question, record:
- Exact question.
- Why it matters / who would use the answer.
- Columns needed.
- Analysis method.
- At least two D1–D6 criteria if Non-ML.
- Two possible plots.
- Feasibility and data limitations.

For the ML candidate, additionally define the target, prediction user, prediction-time features, leakage risks, split strategy, metrics, and candidate models.

### 5. Assign owners and tasks (10–15 min)

Assign one owner per question. Each member owns two questions. Also assign shared tasks such as source/license research, data dictionary, EDA, GitHub maintenance, and presentation coordination.

### 6. Agree on next deliverables

Before ending the meeting, write down:
- Who does what.
- Which branch each person uses.
- What files or findings each person must deliver.
- Deadline for the next check-in.
- Questions that still need instructor clarification.

## Meeting output checklist

- [ ] Team member names and student IDs filled in.
- [ ] Dataset source and license references recorded.
- [ ] CSV inspected and actual shape recorded.
- [ ] Data dictionary started.
- [ ] Prior work / related notebooks list started.
- [ ] Candidate questions collected (not necessarily finalized).
- [ ] D1–D6 coverage checked.
- [ ] ML target and feasibility discussed.
- [ ] Owners and deadlines assigned.
- [ ] Next meeting time agreed.
